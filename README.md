# stopdrooling

stopdrooling（别流口水）是一个 DeepSeek Harness 插件，版本 0.3.0。它在发往模型的请求里只做短语匹配，不做语义判断。大量样本里，这类循环短句经常自己占一段，所以只删除单独成段、并且整段与短语表相同的行。写在段落里面的不处理，因为它们邻接着有意义的内容。

会话记录里的原文保留。装进带网页的 profile 时，被删的行在页面上标红。

插件按 dsh 标签 `dsh-v0.2.0-rc.2` 开发。使用前需要本机已有 dsh CLI、pnpm 10 或以上，Node 为 `^22.19.0 || >=24`。

## 背景

### 推理模型为什么会循环

ICML 2026 的文章 *Wait, Wait, Wait… Why Do Reasoning Models Loop?*（《等等，等等，等等……为什么推理模型会陷入循环？》）研究的问题是：为什么推理模型会反复选择以前执行过的动作，甚至在重复过程中越来越难以摆脱循环。

研究者发现三个相互关联的现象：

1. 学习误差导致动作循环。当正确推进任务的动作较难学会，而重复、回顾、重新确认较容易时，模型可能更倾向选择后者。
2. 错误具有时间相关性。模型在某个决策点偏向某种错误动作后，之后遇到类似决策点，可能再次选择它。
3. 重复本身会强化重复。一旦模型开始循环，继续产生类似内容的倾向可能进一步增强。

这些不是单纯的语言风格猜想。作者进行了开源推理模型测试，并设计了可控制的图路径推理实验来研究机制。

尽管论文研究的是推理过程中的循环机制，还不能直接推广成 DeepSeek V4.1 的 “Let's go / I will do” 就是同一种原因。对得上的是论文第五节 A Catalyst for Looping（循环的催化因素）：模型可能从训练数据中学会一种模式，如果此前已经连续重复，那么接下来继续重复，也像是一种合理的续写。

论文第四节还有一层更细的结果：即使不把已经选择过的动作重新强化，模型对某些动作的微小偏好也会在后续决策中持续存在。作者甚至观察到，模型从未实际选择的第二高概率动作，其偏好也具有时间相关性。论文对下面两者都提供了证据，因此不能把所有复读都归咎于历史思维链没有清除。

- 上下文自我强化：生成过的动作成为后续预测的条件，模型越来越倾向延续已经出现的模式。
- 学习分布的稳定偏差：即使没有简单地模仿刚才的动作，模型仍可能在类似决策点反复偏向同一错误选项。

### 长程执行里的自我条件化

ICLR 2026 的文章 *The Illusion of Diminishing Returns: Measuring Long Horizon Execution in LLMs*（《收益递减的错觉：测量大语言模型的长程执行能力》）研究的是 Self-conditioning（自我条件化）。

研究者人为改变历史对话中错误答案的比例，观察模型在后续任务中的表现。对于所测试的多种非思考模型，历史错误越多，之后出错的概率也越高。这种影响不能单纯用上下文变长来解释。

用直白的话说，模型不仅在读取历史信息，也可能把自己的历史错误当作值得延续的行为示例。

### 思考模式必须回传历史思维链

DeepSeek 当前思考模式 API 有一条已经核实的规则：

| 请求方式 | 旧 `reasoning_content` |
| --- | --- |
| 携带 `tools` | 必须完整回传，并拼接进模型上下文 |
| 不携带 `tools` | 可以不回传；即使回传，也会被 API 忽略 |

携带 `tools` 的请求即使没有实际调用工具，也必须按文档回传历史思维链，否则可能返回 400。因此，在长时间运行、持续使用工具的 DeepSeek Agent 中，历史思维链累积是一条需要重点检查的风险路径。

## 作者的判断

作者自己的实验是：通过 softmax 提高转折词的几率，例如 but、wait、actually，并不能显著提高模型的逻辑能力。观察到的退化和进步可以被解释为随机扰动。

要证明模型在输出或不输出大量 “let's go / I will” 这类停止先行词时能力有没有差异，需要大量实验和消融。作者个人无力承担，也没有相应的任务环境，希望借助社区：请用自己的同一任务，对比使用插件和未使用插件的结果。目前没有第三方盲测平台，可以自行做主观评价，并在 issue 里投票。

期望这个插件能有所帮助，也期望 DeepSeek 团队尽早处理思维链异常，以及能力差异的散布。

## 技术路径

插件挂在发往模型的请求上，只处理思考链的末尾。规则是固定的整段匹配：一行去掉首尾空白后与短语表里的某一条相同，才删除这一段。段落内部出现的同样字样不删。这里没有语义判断。

动作只在思考链末尾，规则机械且固定，同一段重复内容每次得到的结果相同，所以缓存破坏较少。末尾仍会被改动。最恶劣时，被破坏的区域在 100k 以内。这出现在上下文长度达到 384k 及以上、整个上下文只有单轮一段思考链、并且这段思考接近输出上限的时候。如果发现缓存被整段刷新，先停用，并检查是否与其他插件冲突。

作者无法保证修改必然正确。这个插件用 hook 修改请求体，装载前务必自行判断，并阅读 `src/` 和 `client/`。

本插件没有拟人心智，没有 AGI，没有自我认知，也没有白箱智能。

## 安装

从该版本的 GitHub Release 下载 `stopdrooling-0.3.0.tgz`。不要克隆本仓库来安装，也不要执行 `dsh plugin add github:...`。仓库里的开发依赖指向 dsh 源码树，`prepack` 不能在这份仓库外面独立完成构建。

在保存 tarball 的目录执行：

```sh
dsh plugin --profile web add ./stopdrooling-0.3.0.tgz
dsh --profile web --dump-config
dsh web
```

`--dump-config` 里应出现包名 `stopdrooling`。已经开着的进程要重新启动，才读得到新装的插件。

要留着原来的 `web` 作对照：

```sh
dsh --profile web-compare --from-default-profile web --dump-config
dsh plugin --profile web-compare add ./stopdrooling-0.3.0.tgz
dsh --profile web-compare
```

第一条只在 `web-compare` 还不存在时执行。卸下：

```sh
dsh plugin --profile web remove stopdrooling
```

随包的 `cordis.patch.yml` 写了 `remove: paragraph` 和 35 条短语。`tailFraction` 没有写在这份文件里，用的是 schema 默认值 0.25，也就是每个思考块的最后 25%。要改短语或比例，编辑该 profile 的 `cordis.patch.yml`，按 `id: stopdrooling` 把这一行的 `config` 整份写上。漏写的键会回到 schema 默认 `match` 和 `letsgo`，不是包里那 35 条。

## 运行时做的事

宿主挂在 `llm/stream` 上。命中时复制请求，只改发出去的思考文本：

- 只删除整行与短语表完全相同的行，长句里出现的不删。
- 只处理每个思考块的最后 25%。
- 块、顺序、正文和工具调用保留。
- 改过的块去掉 signature。
- 如果删完会变成空块，整块保持原样。
- 没有命中时，原请求原样发出。

会话日志不改。网页标红使用客户端内嵌的 35 条短语和 0.25，不读取宿主上改过的配置。

更细的配置和实现说明在 [docs/plugin.zh.md](docs/plugin.zh.md)，英文稿在 [docs/plugin.en.md](docs/plugin.en.md)。
